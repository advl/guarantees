# guarantees

A scheduler for a repository's guarantees, in two halves. The deciding half is pure. `parseRegister` reads the register of rows — one table per guarantee, its kind, its tier, its test file, its digest-pinned image, its budget — or refuses it wholesale, naming every fault by table, column and line. `planTier` turns a tier's rows into a pool and a serial list, in register order, and `judgeWall` holds the wall-clock span of the whole schedule under the tier's wall. `readReport` reads the test runner's report into the numbers a verdict is judged by, `judgeRun` judges one run from that report and its freshness and never from an exit code, refusing to judge a run that left no report, a stale one or one in which nothing executed, and `toExitCode` maps a verdict or a refusal onto the contract's codes. `readProbe` reads the readings a measuring entry wrote, `computeP95` takes the measured windows of an entry run five times to a p95 by nearest rank, `computeBudget` turns a p95 into a budget by the one rule, and `rewriteRunBudget` writes the pair back into the register text as one replaced line. Nothing in that half touches the filesystem, the network, the clock or a process; the reading and writing around those functions belong to the caller.

The running half starts containers. `probeEngine` probes the container engine once and refuses a machine without it; `resolveImage` finds a digest-pinned image in local storage, whatever its tag, before it pulls; `reapStale` removes what an earlier run of the same checkout left running, and refuses when the engine will not say what is running; and `runEntry` runs one entry through its lifecycle — the work directory cleared, each build recipe in its own container outside the measured window, the freshness marker, the measured run with the repository mounted read-only and the network off, the hard kill by removing the container at three times the budget, the verdict judged from the report the runner wrote, and a teardown on every path out that removes the entry's containers, runs its release recipes on the host, lifts the report and whatever the entry generated for a golden clear of it, and removes the directory. `acceptGolden` is the one path by which a golden changes, taking what a run generated inside the image as the files the next run is compared against, and `proveTier` proves a tier can report a failure at all: it runs the row designed to fail and requires it red, and where the tier holds the row that pins the corpus's bijection it installs a file no row claims, runs that row, and requires that row's one named assertion among the failed. The base image every TypeScript corpus runs in is defined under `images/ts/`, and `./vitest` carries the runner configuration a corpus hands to its own `vitest.config.ts`.

`guarantees` is also an executable, on the path of anything that installs the package, and it is where the two halves meet: `list` prints the register, `check` holds it against what the corpus's runner would collect and against the images the tier resolves, `image` builds an image and records what the rows must pin, `run` runs one entry through its lifecycle, `tier` runs a tier's rows pooled by kind under its wall, `prove` proves a tier, `rebudget` re-measures an entry and writes the pair back, and `accept` runs an entry and takes what it generated as its goldens. Each ends in one of the contract's exit codes.

`./selftest` carries the five bodies a corpus imports rather than re-authors: the bijection between its register and what its runner would collect, the layering between a corpus and the code it judges, the tie between the images a tree defines and the images its rows name, the toolchain an entry actually resolves from inside its image, and the sentinel designed to fail. They ship as bodies because the first of them scans the tree it stands in and has to find itself in it.

The contract is published beside the code. `./contract` carries the version, the exit codes and the five schemas — the register, the runner's report, the probe, the freshness marker and the container labels — as objects, and `./contract/*.schema.json` carries the same five as committed files, the register's carrying the version and the exit codes inside it, emitted from one definition, so an implementation in another language reads a schema rather than a type.
